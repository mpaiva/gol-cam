### Option B: full calibration overlay on the HMI
Implemented over 4 commits as user-feedback drove the UI from a
small panel up to a full-screen modal that repaints the placar
cleanly on dismiss:

- **`1b36d56`** — Option B baseline. `CamState` gained
  `motionTh`, `colorTh`, `calContrast`, `hasCalSnap`, and a 40-byte
  `calMsg`. New `extractStringField()` helper mirrors the existing
  `extractIntField` / `extractBoolField` JSON parsers. New
  `CalOverlay` struct + state machine
  (`RUNNING → RESULT_OK/FAIL → OFF`). `drawCalOverlay()` renders
  title / live `calMsg` / 3-stop progress bar / Cancelar button. Cam
  state transitions (`1 → 0`) trigger the RESULT phase. `ACT_CAL_CANCEL`
  resets the cam and collapses the overlay. Touch hit-test swallows
  taps under the overlay; only Cancelar fires (returns `-2`,
  routed to `ACT_CAL_CANCEL`). 70/70 integration tests still passed.

- **`cb9fe2e`** — polish: `calMsg` buffer bumped 40 → 64 bytes (the
  cam's full failure message is ~61 chars), added a raise-time
  snapshot of `calMsg` plus a 500 ms min-age gate so a stale FAILED
  message from the previous attempt no longer flips the overlay to
  RESULT_FAIL on frame 1 (this was the entire "neither change took"
  user feedback), and rewrote the panel as solid white fillRect (no
  rounded corners) with strong blue text — eliminates corner
  bleed-through. Result phase keeps green/red title colour-coding;
  Cancelar keeps red bg + white text.

- **`a33cb2e`** — overlay is now full-screen (800 × 480) and all
  underlay redraws are gated by `!overlayActive()`. Without this,
  `pollCam`'s `dirtyButtons` flag would punch the green START rect
  through the white overlay (the screenshot that showed "START
  visible inside the white panel"). Same gate on the touch-release
  drawButton(prev/btn) in `serviceTouch()`. Title bumped to text
  size 4 for the bigger canvas, layout reflowed around the new
  dimensions, dismiss path sets `dirtyHeader` too since the header
  is now also under the overlay.

- **`dcb85b7`** — dismiss path now calls `renderFull()` directly
  instead of relying on the loop's per-flag redraws. The loop's
  `dirtyButtons` handler is hard-coded to repaint only button index
  5 (START, the only one whose label changes via pollCam), so
  dismissing the full-screen overlay left the other 7 placar
  buttons white-on-white. Both dismiss paths (state-machine
  auto-dismiss after 3 s and `ACT_CAL_CANCEL`) now do a full
  fillScreen + drawHeader + drawScoreDigits + drawButtons (all 8)
  + drawSideStatus. Added a forward declaration for `renderFull()`.

## Bugs discovered + fixed during user-testing
| # | Symptom | Root cause | Fix |
|---|---|---|---|
| 1 | `calMsg` truncated to "Place dadi" | 40-byte buffer too small | Bump to 64 bytes (cb9fe2e) |
| 2 | Title said "Calibrando" with a FAILED message under it | Cam stays in state=1 for a beat after writing the failure to calMsg | Detect FAILED/FALHOU prefix in calMsg and flip to RESULT_FAIL early (cb9fe2e) |
| 3 | Early-fail flipped on frame 1 | Stale calMsg from the previous attempt was already present | Snapshot calMsg at CAL-tap time + 500 ms min-age gate (cb9fe2e) |
| 4 | "Memory issue with the display" — dark overlay had artifacts | Rounded corners exposed underlying score view through transparent radii | Solid white fillRect + blue text, no rounded corners (cb9fe2e) |
| 5 | Green START leaking through white overlay | `dirtyButtons` from pollCam triggered `drawButton(5)` while overlay was up | Gate the underlay redraws by `!overlayActive()` (a33cb2e) |
| 6 | User expected full-screen overlay | Overlay was 780 × 335, header + side-status visible in black around it | Switch to 800 × 480 + gate dirtyHeader + dirtyStatus too (a33cb2e) |
| 7 | Placar came back "stripped" after overlay dismissed | Loop's dirtyButtons handler only redraws button index 5 (START) | Call `renderFull()` directly in both dismiss paths (dcb85b7) |
